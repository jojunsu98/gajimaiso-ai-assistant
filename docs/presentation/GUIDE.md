## 자료를 보는 순서

1. [발표 슬라이드 내용](SLIDES.md)을 읽어 전체 흐름을 익힙니다.
2. [발표 스크립트](SCRIPT.md)를 소리 내어 읽습니다. 각 장의 ‘화면 안내’는 행동 지시이므로 읽지 않습니다.
3. [PowerPoint](gajimaiso-presentation.pptx)를 엽니다. 슬라이드 노트에도 같은 대본과 출처를 넣었습니다. 발표자 보기를 사용할 수 있으면 화면과 대본을 나눠 볼 수 있습니다.
4. [예상 질문·답변](Q_AND_A.md)을 확인하고, 실제로 이해한 표현으로 답해 봅니다.

8분은 구성 기준이며 실제 낭독 시간을 측정한 결과는 아닙니다. 화면을 가리키는 시간을 포함해 한 번 연습한 뒤 속도를 조절하세요. 자료에는 새 GPT 호출을 해야만 진행할 수 있는 순서를 넣지 않았습니다.

## 발표의 중심 내용

> 저장된 데이터를 읽고, 핵심 내용을 정리해 AI에 전달하고, 답변을 저장해 다시 볼 수 있게 만들었습니다.

이 문장을 중심으로 설명합니다. 기술 이름을 많이 외워서 말하는 것보다 **사용자가 무엇을 하고, 서비스가 어떻게 처리하며, 어떤 화면으로 확인했는지**를 연결하는 것이 중요합니다.

| 발표 구간 | 보여줄 내용 | 듣는 사람이 이해하면 되는 점 |
| --- | --- | --- |
| 1~3장 | 소개·목차·만든 이유 | AI에게 내 자료를 전달하는 과정이 필요함 |
| 4장 | 창원시 월별 순이동128건 | 무엇을 분석하며 무엇을 뜻하는 숫자인지 |
| 5~6장 | 질문 처리와 요약 전달 | 화면 뒤에서 자료를 읽고 AI에 건네는 흐름 |
| 7~9장 | 채팅·자료 추가·이전 질문 | 실제로 동작한 화면과 확인 방법 |
| 10~11장 | 안전장치·검증 결과 | 성공 조건과 확인한 범위를 구분하는 태도 |
| 12장 | 한계·다음 개선 | 구현 범위와 향후 과제를 혼동하지 않음 |

## 어려운 용어를 쉽게 말하는 방법

쉬운 설명을 먼저 하고, 필요한 경우에만 괄호 안 용어를 덧붙입니다. 비유는 이해를 돕는 말이며 실제 저장 위치나 권한 구조를 완전히 설명하는 것은 아닙니다.

| 용어 | 발표에서 먼저 할 말 | 덧붙일 때 주의할 점 |
| --- | --- | --- |
| 시계열 데이터 | 시간 순서대로 쌓인 기록 | 이 프로젝트는 월별 기록 |
| 순이동 | 들어온 사람 수에서 나간 사람 수를 뺀 값 | 출생·사망을 포함한 전체 인구 증감이 아님 |
| 프론트엔드 | 사용자가 보는 화면 | HTML은 내용, CSS는 모양, JavaScript는 동작 담당 |
| 백엔드·서버 | 화면 뒤에서 자료를 읽고 처리하는 부분 | 이 프로젝트는 FastAPI 사용 |
| 데이터베이스 | 자료와 대화를 보관하는 저장소 | Firestore는 이 저장소에 사용한 서비스 이름 |
| 컬렉션 | 종류별로 나눠 둔 자료 묶음 | 실제 컴퓨터의 파일 폴더와 완전히 같지는 않음 |
| API | 화면이 서버에 일을 요청하는 약속된 통로 | 요청과 응답의 형식을 정해 둔 것 |
| CRUD | 추가·조회·수정·삭제 | 영어 약자를 먼저 외우게 하지 않기 |
| 요약 | 기간·개수·평균·최근 흐름을 정리한 내용 | 이 프로젝트의 숫자 계산은 서버가 담당 |
| 시스템 프롬프트 | AI에게 주는 답변 기준과 참고 정보 | 지침을 줘도 오답 가능성이 완전히 사라지지는 않음 |
| 컨텍스트 주입 | AI에게 질문과 함께 자료 요약을 건네는 것 | 모델을 새로 학습시키는 것이 아님 |
| Pydantic | 날짜·숫자·길이가 정한 형식인지 확인하는 검사 도구 | 프론트 검사만 믿지 않고 서버에서도 검사 |
| 접근 토큰 | 보호된 기능을 열 때 확인하는 값 | GPT 비밀키와 다르며 이 앱은 단일 관리 권한 |
| 환경변수 | 코드 밖에서 넣는 실행 설정 | 비밀키도 이 방식으로 관리하지만 공개 설정도 있음 |
| CORS | 어느 웹 주소에서 서버를 이용할지 정하는 브라우저 규칙 | 사용자 인증이나 모든 외부 요청 차단을 대신하지 않음 |
| 콜드스타트 | 쉬고 있던 서버가 다시 켜지는 대기 시간 | 첫 화면이 느릴 수 있어 안내와 조회 대기 제공 |
| Swagger·OpenAPI | 서버가 받는 요청과 돌려주는 결과의 안내서 | 안내서가 열린 것만으로 AI·DB 성공을 증명하지 않음 |
| 브랜치 | 같은 프로젝트에서 작업 버전을 따로 관리하는 가지 | 이번 발표용 가지를 만들었고 main에 합치지는 않음 |

## 실제 화면을 보여주는 순서

기본 발표는 PPT에 포함한 실제 캡처로 진행할 수 있습니다. 인터넷이 없어도 설명할 수 있고, 원본 자료를 바꿀 필요가 없습니다.

| 순서 | 보여줄 화면 | 가리킬 곳 | 설명 문장 |
| --- | --- | --- | --- |
| 1 | [요약과 GPT 문답](../submission/screenshots/06-gpt-summary-live-2026-11-04.jpg) | 요약 수치와 답변 속 같은 수치 | “서버가 정리한 자료를 참고해 설명합니다.” |
| 2 | [자료 추가 결과](../submission/screenshots/08-crud-create-result-2026-11-04.jpg) | 추가 완료 안내와 목록1건 | “실제 저장소의 별도 시험 공간에서 추가를 확인했습니다.” |
| 3 | [이전 질문 복원](../submission/screenshots/07-history-restored-live-2026-11-04.jpg) | 선택된 질문과 불러오기 안내 | “이때는 AI에게 다시 묻지 않고 저장된 답변을 읽습니다.” |

원본 캡처는 전체를 보존했습니다. 7장의 세로 화면은 슬라이드에서 글자가 작게 보일 수 있어 핵심 수치를 큰 글씨로 함께 적었습니다. 질문을 자세히 보여줄 때는 위 원본 이미지 링크를 열어 확대하세요.

**선택적 실시간 시연:** 공개 웹에서 요약을 보여주고, 기존에 허용된 접근 방식이 준비되어 있다면 이전 질문을 선택해 불러옵니다. 이번 자료 제작 과정에서 새 시연이나 GPT 호출을 실행한 것은 아닙니다. 새 GPT 질문은 필요할 때만 별도 판단하고, 기존 운영 자료의 수정·삭제는 시연에 사용하지 않습니다.

서버가 늦게 뜨면 “무료 서버가 쉬고 있다가 다시 켜지는 중이라 잠시 걸릴 수 있습니다”라고 설명하고 준비한 캡처로 이어갑니다. 질문 버튼을 반복해서 누르지 않습니다. 실패 시 “저장 여부를 목록에서 먼저 확인하겠습니다”라고 말합니다.

## 발표 전 준비

- [ ] PowerPoint에서 한글과 이미지가 보이는지 직접 열어 확인합니다.
- [ ] 발표 화면은 청중용 슬라이드, 대본은 개인 화면으로 분리합니다.
- [ ] 핵심 문장과 ‘순이동’의 뜻을 자기 말로 설명해 봅니다.
- [ ] 이미지 확대가 필요하면 원본3장을 미리 엽니다.
- [ ] 실시간 시연을 선택했다면 공개 웹을 먼저 열어 서버 기동을 기다립니다.
- [ ] 비밀키·환경설정·접근 토큰을 발표 화면에 띄우지 않습니다.
- [ ] ‘100%’는 네이토 사전평가 결과라고 말합니다.
- [ ] 소리 내어 읽으면서 시간을 재고, 빠르면 여유를 두고 화면을 짚습니다.

## 시간에 맞춰 줄이는 방법

- **약8분:** 12장 전체 사용. 슬라이드별 기준 시간은 대본에 있습니다.
- **약5분:** 2장의 목차를 한 문장으로 줄이고, 5~6장을 합쳐 ‘자료 요약을 AI에 전달한다’고 설명합니다. 10장은 안전장치 두 가지만 소개합니다.
- **약3분:** [대본 마지막의 짧은 버전](SCRIPT.md#short-script)을 읽으며 1·4·5·7·8·9·11·12장만 보여줍니다.

시간이 부족하더라도 ‘시험용 CRUD 자료’, ‘기존 답변 복원’, ‘사전평가와 최종평가의 차이’라는 설명은 남깁니다.
